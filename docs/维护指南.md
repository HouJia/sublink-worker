## 1. 定位与差异

本仓库是 **7Sageer/sublink-worker 的 HouJia fork**，在 upstream 之上增加：

- **子路径** `/sublink/`（`BASE_PATH` + `src/runtime/basePath.js`）
- `fork/docker/` 与 NPM 片段
- Node + Redis 自托管（上游 Cloudflare Workers 为主）

分支模型见 [`技术方案-分支与上游同步.md`](技术方案-分支与上游同步.md)。

## 2. 日常开发流程

```bash
git checkout hjs-feature
git pull origin hjs-feature
# … 改代码 …
npm run build:node
git commit -m "feat(scope): 摘要"
git push origin hjs-feature
# 验证通过后
git checkout hjsmaster && git merge hjs-feature && git push origin hjsmaster
```

**禁止**：在 `hjsmaster` 上直接开发；在 `upstream/main` 上提交 HouJia 定制。

## 3. 构建与镜像

| 方式 | 命令 | 产出 |
|---|---|---|
| Node 包 | `npm run build:node` | `dist/node-server.cjs` |
| Docker（NAS） | `docker build -f fork/docker/Dockerfile.fork -t sublink-worker:hjs-fork .` | 健康检查 `/sublink/` |

环境变量（`.env.example`）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `BASE_PATH` | `/sublink` | 剥前缀与前端 `APP_BASE_PATH` |
| `PORT` | `8787` | 容器内监听 |
| `REDIS_HOST` | `127.0.0.1` | KV 存储 |
| `PUBLIC_ORIGIN` | 空 | 订阅外链固定公网域名时用 |

**注意**：`normalizeRuntime` 必须保留 `config.basePath`，否则页面 `window.APP_BASE_PATH` 会为空。

## 4. QNAP 运维

| 项 | 值 |
|---|---|
| 容器 | `sublink-worker`、`sublink-redis` |
| 宿主机端口 | **58087** → 容器 `8787` |
| 公网 | `https://houjia.mycloudnas.com:44/sublink/` |
| NPM 片段 | `fork/docs/npm-server_proxy.snippet.conf` |

QNAP 上 NPM 容器访问 `192.168.0.6:8787` 可能超时，**须映射 58087** 并在 `proxy_pass` 中使用该端口。

升级步骤：

1. 本机 `linux/amd64` 构建：`docker buildx build --platform linux/amd64 -f fork/docker/Dockerfile.fork -t sublink-worker:hjs-fork --load .`
2. `docker save | ssh nas-qnap docker load`
3. `docker rm -f sublink-worker` 后用相同环境变量 `docker run`（`BASE_PATH=/sublink`，网络 `sublink-net`）
4. 验收：`curl -s http://127.0.0.1:58087/sublink/ | grep APP_BASE_PATH` 应为 `"/sublink"`

## 5. 分流规则怎么维护

Sublink 通过 **GeoSite 类别勾选** 生成 Clash / Surge / Sing-box / **subconverter ini**：

- 页面勾选类别 → 生成 `/sublink/clash?...`、`/sublink/subconverter?...` 等
- 适合 **单人、按需 B/C 套餐**（如仅 Google+AI、仅社交视频）
- **无多用户**；多人各拿不同规则请用妙妙屋

不能把成熟 `config-template.ini` **原样导入**类别模式；若要坚持 ini 模板链，继续用 SubConverter-Extended 的 `/subapi?config=...`。

## 6. 与 sub-web / subapi 的边界

| 链路 | 产出 | 适用 |
|---|---|---|
| **Sublink / 妙妙屋** | 自带 rule-providers + 类别 | 勾选式按需规则 |
| **sub-web + /subapi** | ini 模板 → SubConverter | 成熟 ini、复杂策略组 |

两者可并存，不要混为一谈「都必须经 subconverter」。

## 7. 故障速查

| 现象 | 排查 |
|---|---|
| 页面链接缺 `/sublink` | 查 `APP_BASE_PATH`；修 `runtimeConfig.js` 保留 `basePath` |
| NPM 502 / 超时 | 改用 **58087** 端口，勿直连 8787 |
| Redis 连不上 | `docker network inspect sublink-net`；`REDIS_HOST=sublink-redis` |
| 上游合并后子路径失效 | 保留 `basePath.js`、`wrapFetch` 与 `fork/` 目录 |
