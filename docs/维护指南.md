## 1. 定位与差异

本仓库是 **7Sageer/sublink-worker 的 HouJia fork**，在 upstream 之上增加：

- **子路径** `/sublink/`（`BASE_PATH` + `src/runtime/basePath.js`）
- `fork/docker/` 与 NPM 片段
- Node + Redis 自托管（上游 Cloudflare Workers 为主）

分支模型见 [`技术方案-分支与上游同步.md`](技术方案-分支与上游同步.md)。

## 2. 日常开发流程

```bash
git checkout hjs-feature

git commit -m "feat(scope): 摘要"
```

## 3. 构建与镜像

| 方式 | 命令 | 产出 |
|---|---|---|
| Node 包 | `npm run build:node` | `dist/node-server.cjs` |
| Docker（NAS） | `docker build -f fork/docker/Dockerfile.fork -t sublink-worker:hjs-fork .` | 健康检查 `/sublink/` |

环境变量（`.env.example`）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `BASE_PATH` | `/sublink` | 剥前缀与前端 `APP_BASE_PATH` |
| `PORT` | `8787` | 容器内监听 |
| `REDIS_HOST` | `127.0.0.1` | KV 存储 |
| `LAN_SERVICE_BASE` | 空 | Subconverter 模块**底部**展示的内网完整 config URL（如 `http://192.168.0.6:58087/sublink`） |
| `PUBLIC_ORIGIN` | 空 | 可选；默认不设置，复制链接跟随浏览器访问域名 |

**注意**：`normalizeRuntime` 必须保留 `config.basePath`，否则页面 `window.APP_BASE_PATH` 会为空。

页面「Subconverter 外部配置」复制出的 URL **跟随当前访问域名**（公网或内网），**不要**在 SubConverter 服务侧写死内网地址。

## 4. QNAP 运维

| 项 | 值 |
|---|---|
| 容器 | `sublink-worker`、`sublink-redis` |
| 宿主机端口 | **58087** → 容器 `8787` |
| 公网 | `https://houjia.mycloudnas.com:44/sublink/` |
| NPM 片段 | `fork/docs/npm-server_proxy.snippet.conf` |

QNAP 上 NPM **公网反代使用宿主机 `192.168.0.6:58087`**（与 mmw `8080` 一致）。**前提**：`sublink-worker` 须在 Docker **默认 bridge** 上；若仅挂自定义 `sublink-net`，NPM 容器经宿主机 IP 访问 `58087` 会 hairpin 超时（见 `docs/QNAP部署回顾-2026-06.md`）。

内网用户仍可直接 **`http://192.168.0.6:58087/sublink/`**。

升级步骤：

1. 本机 `linux/amd64` 构建：`docker buildx build --platform linux/amd64 -f fork/docker/Dockerfile.fork -t sublink-worker:hjs-fork --load .`
2. `docker save | ssh nas-qnap docker load`
3. `docker rm -f sublink-worker` 后用相同环境变量 `docker run`（`BASE_PATH=/sublink`，网络 `sublink-net`）
4. 验收：`curl -s http://127.0.0.1:58087/sublink/ | grep APP_BASE_PATH` 应为 `"/sublink"`

## 5. 分流规则怎么维护

Sublink 通过 **GeoSite 类别勾选** 生成 Clash / Surge / Sing-box / **subconverter ini**：

- 页面勾选类别 → 生成 `/sublink/clash?...`、`/sublink/subconverter?...` 等
- 适合 **单人、按需 B/C 套餐**（如仅 Google+AI、仅社交视频）
- **无多用户**；多人各拿不同规则请用妙妙屋

不能把成熟 `config-template.ini` **原样导入**类别模式；若要坚持 ini 模板链，继续用 SubConverter-Extended 的 `/subapi?config=...`。

**修改勾选列表**（对应页面「规则选择」）：

| 文件 | 内容 |
|---|---|
| `src/config/rules.js` | `UNIFIED_RULES`（名称 ↔ GeoSite/IP 列表）、`PREDEFINED_RULE_SETS`（minimal/balanced/comprehensive） |
| `src/config/ruleGenerators.js` | 生成 Clash rule-providers / 路由顺序 |
| `src/config/subconverterConfig.js` | 将同一套规则转为 subconverter ini |

**clash-verge-split-kit** 的 `verge/derive/parts/` 是独立 ini 体系，**不能一键导入**；可并行使用 `/subapi?config=houjia-template.ini`，或人工把策略意图迁到 `UNIFIED_RULES`。

### 5.1 Subconverter 外部配置 URL

页面「Subconverter 外部配置」复制的是 **ini 模板的 HTTP 地址**（Sublink 自身提供，供 SubConverter 的 `config=` 拉取）。URL **跟随你打开页面时的域名**：

- 公网打开 → `https://houjia.mycloudnas.com:44/sublink/subconverter?...`
- 内网打开 → `http://192.168.0.6:58087/sublink/subconverter?...`

内网完整 config URL 显示在 **Subconverter 外部配置模块底部**（`LAN_SERVICE_BASE` + 当前规则参数）；家庭导航页 `/index/` 可选 Local 模式。

## 6. 与 sub-web / subapi 的边界

| 链路 | 产出 | 适用 |
|---|---|---|
| **Sublink / 妙妙屋** | 自带 rule-providers + 类别；可选 `/subconverter` 导出 ini | 勾选式按需规则 |
| **sub-web + /subapi** | ini 模板 → SubConverter 进程转换节点 | 成熟 ini、复杂策略组 |

**澄清**：

- 妙妙屋 / Sublink **可直接**生成带分流策略的 **Clash YAML**（`/clash?url=机场`），**不必**经 SubConverter。
- 两者也**可以**导出组装的 ini（Sublink 的 `/subconverter` 端点），供 SubConverter 当 `config=` **外部模板**；机场节点仍由 SubConverter 合并。
- 不能把 verge kit 的完整 ini **原样导入**类别勾选 UI。

两者可并存，不要混为一谈「都必须经 subconverter 进程」。

## 7. 故障速查

| 现象 | 排查 |
|---|---|
| 页面链接缺 `/sublink` | 查 `APP_BASE_PATH`；修 `runtimeConfig.js` 保留 `basePath` |
| NPM 502 / 超时 | `network connect sublink-net` + `proxy_pass http://sublink-worker:8787`（容器名） |
| Redis 连不上 | `docker network inspect sublink-net`；`REDIS_HOST=sublink-redis` |
| 上游合并后子路径失效 | 保留 `basePath.js`、`wrapFetch` 与 `fork/` 目录 |
