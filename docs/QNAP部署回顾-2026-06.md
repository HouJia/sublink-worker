## 1. 部署概要

| 项 | 值 |
|---|---|
| 公网 | `https://houjia.mycloudnas.com:44/sublink/` |
| 内网直连 | `http://192.168.0.6:58087/sublink/` |
| 容器 | `sublink-worker` + `sublink-redis`，网络 `sublink-net` |
| env | `BASE_PATH=/sublink`，`LAN_SERVICE_BASE=http://192.168.0.6:58087/sublink` |

## 2. 公网慢/无响应（NPM）

**现象**：局域网 `58087` 正常，公网 `/sublink/` 超时；同期 `/mmw/`（`8080`）正常。

**根因（QNAP Container Station）**：不是「58087 被防火墙单独封禁」，而是 **Docker 网络挂载方式**：

| 服务 | 容器网络 | NPM → `192.168.0.6:端口` |
|---|---|---|
| 妙妙屋 | 默认 **bridge** | ✅ `8080` 可达 |
| Sublink（修复前） | **仅** 自定义 `sublink-net` | ❌ `58087` hairpin 超时 |
| Sublink（修复后） | **bridge** +（可选）sublink-net | ✅ `58087` 可达 |

自定义 bridge 上发布的宿主机端口，在 QNAP 上常无法被 **另一 bridge 上的 NPM 容器** 经宿主机 LAN IP 访问；mmw 一直在默认 bridge，故无此问题。

**修复（与 mmw 对齐）**：

```bash
# 部署时 worker/redis 须在默认 bridge（见 fork/docker/docker-compose.fork.yml）
docker network connect bridge sublink-worker   # 已有容器补救

# NPM 与 mmw 相同，反代宿主机端口：
# proxy_pass http://192.168.0.6:58087;
```

备选：NPM `network connect sublink-net` + `proxy_pass http://sublink-worker:8787`（不如 bridge 方案统一）。

## 3. 内网与 Subconverter 外部配置 URL

- 页面「Subconverter 外部配置」主 URL **跟随当前访问域名**（不强制内网、不改 SubConverter 服务）。
- **内网完整 config URL** 显示在 Subconverter 模块**底部**（`LAN_SERVICE_BASE` + 当前规则参数）。
- 家庭导航 `/index/` 可选 **Local** 打开内网入口。
